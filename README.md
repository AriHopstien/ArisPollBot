# מערכת ניהול סקרים - בוט טלגרם + ממשק Swing

מימוש מלא של המפרט: קהילת משתמשים גלובלית בטלגרם, יצירת סקרים (ידנית או
דרך ChatGPT API) מממשק ניהול ב-Java Swing, ומעקב חי אחר ההשתתפות והתוצאות.

תהליך Java יחיד. אין בסיס נתונים חיצוני ואין שרת נפרד - הבוט וה-GUI הם שני
threads באותו תהליך, משתפים מקור אמת יחיד (`AppState`) ומתואמים דרך
Observer pattern (`EventBus`) כך שה-GUI מתעדכן בזמן אמת בלי polling ובלי
כפתור Refresh.

## ארכיטקטורה

```
                    ┌─────────────────────┐
                    │   AppState (יחיד)    │
                    │  Community + Poll    │
    ┌──────────────▶│  נוכחי + EventBus    │◀──────────────┐
    │               └─────────────────────┘                │
    │                          │                            │
    │                    publish(event)                     │
    │                          ▼                             │
┌─────────┐          ┌──────────────────┐           ┌──────────────┐
│  Bot     │  קורא/   │   PollManager    │  callbacks │  Swing GUI   │
│  thread  │  כותב    │  (טיימרים, מחזור │  (activate/│  EDT thread  │
│(polling) │─────────▶│   חיים של סקר)   │  reminder/ │(3 פאנלים,    │
└─────────┘          └──────────────────┘  close)    │ subscribe)   │
                                                        └──────────────┘
```

כל שינוי ב-state (הצטרפות, תשובה, שינוי מצב סקר) משודר כ-`AppEvent` דרך
ה-`EventBus`, וכל פאנל ב-Swing שנרשם אליו מתעדכן אוטומטית על ה-EDT.
הבוט לעולם לא נוגע ברכיבי Swing ישירות, וה-GUI לעולם לא קורא ל-Telegram
API ישירות - כל התיאום עובר דרך `AppState`/`PollManager`/`EventBus` בלבד.

### החלטת ארכיטקטורה: ללא ספריות חיצוניות

הסביבה שבה נכתב הקוד הזה לא הייתה מסוגלת להוריד תלויות מ-Maven Central
(אין לה גישת רשת לשם), ולכן התקבלה החלטה מכוונת לבנות הכל **ללא אף ספריית
JSON חיצונית וללא ספריית Telegram Bot** - רק JDK סטנדרטי:

- **תקשורת HTTP** (גם מול Telegram וגם מול OpenAI) - `java.net.http.HttpClient`
  הסטנדרטי, כולל long polling מול `getUpdates`.
- **פענוח/בניית JSON** - מיני-פרסר עצמאי ב-`pollsystem.util.Json`
  (כ-250 שורות, נבדק בפירוט - ראו "מה נבדק" למטה).
- **הצבעה** - כפתורי inline keyboard (הודעות + כפתורי בחירה), לא מנגנון
  הסקרים המובנה של Telegram. המפרט (סעיף 6) מתיר את שתי הדרכים; נבחרה
  האפשרות הזו כי היא נותנת שליטה מלאה על טקסט האישור אחרי כל תשובה
  ("בחרת: X") ועל הסרת הכפתורים אחרי מענה - התאמה ישירה לדגש ה-UX במפרט.

**זו לא בהכרח ההמלצה היחידה.** אצלכם, עם גישת אינטרנט מלאה, יש טעם טוב
לשקול להחליף את `pollsystem.util.Json` ב-Jackson/Gson ואת שכבת ה-HTTP
הידנית ב-`org.telegram:telegrambots` - זה יקצר קוד ויוריד תחזוקה. השארתי
את זה כפי שהוא כי זה מה שהיה ניתן לבדוק בפועל (קומפילציה **וגם** הרצה)
בסביבה שבה נכתב.

## הגדרה (חד-פעמי)

1. **בוט טלגרם**: פתחו שיחה עם [@BotFather](https://t.me/BotFather),
   שלחו `/newbot`, ובסוף התהליך תקבלו טוקן (מחרוזת בסגנון
   `123456:ABC-DEF...`).
2. **מפתח OpenAI**: צרו מפתח ב-
   [platform.openai.com/api-keys](https://platform.openai.com/api-keys).
3. העתיקו את `config.properties.example` ל-`config.properties` באותה
   תיקייה, ומלאו את שני הערכים (או הגדירו `TELEGRAM_BOT_TOKEN` ו-
   `OPENAI_API_KEY` כמשתני סביבה - הם גוברים על הקובץ).

## בנייה והרצה

**אפשרות א' - IntelliJ / Maven:** פתחו את התיקייה כפרויקט Maven (IntelliJ
יזהה את ה-`pom.xml` אוטומטית), הריצו `pollsystem.Main`.

**אפשרות ב' - שורת פקודה, בלי Maven:**
```bash
./build.sh   # javac -encoding UTF-8 -d out ...
./run.sh     # java -cp out pollsystem.Main
```
דורש JDK 17 ומעלה. זו בדיוק השיטה שבה הקוד נבדק (ראו למטה) - הכי מובטחת
לעבוד בלי תלות בזמינות Maven Central.

## החלטות עיצוב והנחות מפורשות

המפרט מדויק מאוד ברוב המקומות, אבל יש כמה נקודות שבהן היה עליי לבחור
פרשנות סבירה. מפורט כאן בכוונה ובמפורש, כדי שלא יתקבל כמובן מאליו:

| # | נושא | ההחלטה שהתקבלה | הנימוק |
|---|------|-----------------|--------|
| 1 | "מתי סקר *מתחיל*" (סעיף 5) | ה-snapshot של המשתתפים נלקח ברגע **ההפעלה בפועל** (סוף ה-Countdown), לא ברגע היצירה | מי שמצטרף במהלך ה-Countdown עדיין נכלל; רק מי שמצטרף אחרי שהסקר כבר נשלח בפועל לא נכלל. עקבי גם עם תזמון התזכורת/הסגירה (3/5 דקות מ-"תחילת" הסקר) |
| 2 | התאמת "Hi" (סעיף 1) | לא תלוית רישיות (`hi`/`Hi`/`HI`) | UX - אין סיבה לדרוש רישיות מדויקת; "היי" בעברית ממילא לא מבחין רישיות |
| 3 | הודעה למי ששולח טקסט אחר ולא חבר | תגובה עדינה שמכוונת איך להצטרף | לא גורמת הצטרפות בפועל, רק הודעה - לא מנוגד ללשון הסעיף. **ניתן להסיר בקלות** אם רוצים דיוק מקסימלי ללשון המפרט |
| 4 | הודעה למי שכבר חבר ומנסה "להצטרף" שוב | "כבר רשומ/ה בקהילה" | לא נדרש במפרט, אבל בלי זה המשתמש לא מקבל שום אינדיקציה שהפעולה לא עשתה כלום |
| 5 | עמודת "שם" מול "Telegram Username" (סעיף 2) | שם = `first_name`+`last_name` מטלגרם; Username = `@handle` | הפירוש היחיד שהופך את שתי העמודות לשונות זו מזו |
| 6 | תוצאות עם שוויון בהצבעות (סעיף 11) | סדר ההזנה המקורי נשמר כטיברייקר (מיון stable) | המפרט לא מגדיר טיברייקר; stable sort הוא הבחירה הכי פחות שרירותית |
| 7 | הודעת סיום למשתתפים כשסקר נסגר | נשלחת ("הסקר הסתיים, תודה שהשתתפת") | לא נדרש במפרט (שמדבר רק על הצגת תוצאות ל**יוזם** ב-Swing), אבל UX גרוע להשאיר משתמשים בלי שום סגירה. **ניתן להסיר** ב-`PollDispatcher.notifyPollClosed` |
| 8 | נטרול כפתור "התחל סקר" כשיש פחות מ-3 חברים | הכפתור מנוטרל מראש + תווית מסבירה, לא רק הודעת שגיאה אחרי לחיצה | מניעת פעולה שגויה עדיפה על הודעת שגיאה אחריה - דגש UX מפורש במפרט |
| 9 | פלט ChatGPT שחורג מ-1-3 שאלות / 2-4 אפשרויות | נחתך/מסונן אוטומטית בשקט (לא נדחה כליל) | מודלים לפעמים חורגים מעט מהנחיות; עדיף לתקן בשקט מאשר להכשיל את כל היצירה |
| 10 | ולידציה נוספת בטופס הידני (טקסט לא ריק, 1-3 שאלות, 2-4 אפשרויות) | נאכפת ב-GUI לפני שליחה | לא explicit בסעיף 3 אך נגזר ישירות ממנו; חלק בלתי נפרד מ"ממשק ברור ונעים" |

כל התוספות המסומנות "לא נדרש במפרט" ממוקמות בבירור בקוד (חיפוש `PollDispatcher`
ו-`PollTelegramBot` עם הערה "תוספת UX") ואפשר להסיר אותן בלי לגעת בשום דבר אחר.

## מה נבדק בפועל, ומה לא

**נבדק ואומת (קומפילציה + הרצה בפועל):**
- קומפילציה מלאה של 22 קבצי המקור, ללא שגיאות (`javac -Xlint:all` - רק
  אזהרות `serialVersionUID` קוסמטיות, שכיחות בכל קוד Swing/Exception).
- מחזור חיים מלא של סקר: יצירה → הפעלה (snapshot נכון של 3 משתתפים) →
  תשובות (כולל דחיית תשובה כפולה) → סגירה אוטומטית מוקדמת כשכולם השלימו →
  חישוב תוצאות + מיון יורד לפי שכיחות - הכל דרך `PollManager` האמיתי.
- פרסר/serializer ה-JSON העצמאי: round-trip על אובייקטים מקוננים,
  מערכים, בריחות (`\"`, `\n`, `\t`), עברית, ופענוח payload בצורת
  Telegram `getUpdates` אמיתית (כולל `callback_query`).
- ולידציית `Question` (דחיית 1 או 5 אפשרויות, קבלת 2-4).
- דחיית הצטרפות כפולה לקהילה.
- טעינת `AppConfig` נכשלת עם הודעת שגיאה ברורה בעברית כשאין טוקן/מפתח.
- לולאת ה-polling של הבוט **לא קורסת** כשאין גישת רשת (משדרת שגיאה,
  ישנה 2 שניות, מנסה שוב - נבדק על תהליך חי).

**לא ניתן היה לבדוק בסביבה הזו** (אין גישת רשת ל-`api.telegram.org` או
`api.openai.com`, ואין תצוגה גרפית להרצת Swing בפועל):
- קריאות אמיתיות ל-Telegram Bot API (`sendMessage`, `getUpdates` מול
  שרת אמיתי, `answerCallbackQuery` וכו').
- קריאות אמיתיות ל-OpenAI API (מבנה ה-JSON שנשלח נבדק ידנית מול
  התיעוד, אך לא הורץ מול שרת אמיתי).
- רינדור בפועל של חלונות ה-Swing (הלוגיקה מאחורי כל פאנל נבדקת, אך לא
  "נראתה" בפועל על מסך).

**מומלץ בחום:** להריץ עם טוקן/מפתח אמיתיים ולוודא ידנית שהתקשורת מול
Telegram ו-OpenAI עובדת כצפוי, ושה-GUI נראה ומתנהג כמצופה על מסך אמיתי -
זה בדיוק החלק שלא היה ניתן לאמת כאן.

## הרחבות אפשריות (לא ממומשות, מעבר לדרישות המפרט)

- ביטול סקר ידני על ידי היוזם (המפרט לא מגדיר פעולת "leave"/"cancel")
- שמירת היסטוריית סקרים קודמים לצפייה חוזרת
- Fallback ליצירה ידנית אם קריאת ChatGPT נכשלת שוב ושוב
